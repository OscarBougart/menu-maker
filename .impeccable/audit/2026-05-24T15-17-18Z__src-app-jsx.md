## Executive Summary

**16/20 — Good. -1 from prior 17/20.**

The theme.js refactor is a meaningful architecture upgrade. The regression is a semantic mismatch: `--black` now resolves to the light canvas color, which is used in the menu-sheet box-shadow, producing an invisible shadow. The new blue theme also introduces two contrast failures from the old token names.

## Priority Issues

**[P1] Menu-sheet drop shadow is invisible** — `.menu-sheet { box-shadow: 0 50px 140px color-mix(in srgb, var(--black) 80%, transparent); }` — `--black` → `#f7f9fc`. Fix: `box-shadow: 0 50px 140px oklch(8% 0.01 240 / 0.55);`

**[P1] Button hover text contrast fails WCAG AA** — `.btn:hover { color: var(--black) }` — `#f7f9fc` on `#3b8bbc` ≈ 4.1:1. Fix: `color: #ffffff` (4.7:1, passes AA).

**[P2] Chip active text contrast borderline/failing** — `.style-chip.active`, `.font-chip.active`, `.preset-chip.active` use `color: var(--brass)` = `#3b8bbc` on dark panel ≈ 4.0:1. Fix: switch to `var(--accent-bright)` = `#62b8f0` (≈6.5:1).

**[P2] Status badge removed from canvas-bar** — Status state variable set throughout but never displayed. Success/idle states silent. CSS rules for `.status` and `.status.status-error` are dead code. Restore the `<span className="status">` element in the canvas-bar.

**[P2] Dead CSS** — `.status`, `.status.status-error`, `.style-bar`, `.font-bar`, `.font-row`, `.font-role-label`, `.style-role-label`, `.style-divider` — all defined, none consumed in current DOM.

**[P3] `--chrome` contrast in labels** — `#6a90aa` on `#0f2940` ≈ 4.2:1 for 9px all-caps. Fix: switch `.panel-header .kicker` and `.block-title` to `var(--panel-text-dim)` = `#8aaac8` (5.5:1).

**[P3] Panels missing explicit z-index** — Canvas-bar at z-index 10; panels have none. Add `z-index: 1` to `.panel` for explicit stacking.

**[P3] No `--shadow-base` token** — The `--black` → light-color inversion is a latent bug. Add an explicit dark shadow token to theme.js.
