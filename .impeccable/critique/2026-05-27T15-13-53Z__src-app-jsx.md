## Anti-Patterns Verdict

LLM assessment: The three-panel layout is well-executed but entirely conventional. The blue accent palette (#3b8bbc) is the main slop signal — PRODUCT.md explicitly names "blue-primary button hierarchies" as an anti-reference, yet the current theme is exactly that. CSS variable names still say --brass, --blood, --bone — the previous palette had warmth and specificity. The current one has neither.

Deterministic scan: detector binary unavailable. Manual scan performed. No side-stripe borders, no gradient text, no glassmorphism, no hero-metric template. Saved-menus card grid uses per-menu color variables — smart avoidance of identical-card-grid pattern.

Browser visualization: skipped — no dev server running.

## Overall Impression

The core mechanic is impressive and the preview quality earns the product's purpose. What's holding it back is a color identity crisis: the theme was recently shifted to a blue SaaS palette that directly contradicts the craft-and-warmth brand this studio is supposed to embody.

## What's Working

1. Saved-menus cards render with each menu's own palette — a small touch that makes the grid feel like a real collection. Exactly the kind of earned detail PRODUCT.md calls for.
2. The rules card after extraction: italic aesthetic summary in Cormorant Garamond, swatch row, and bullet rules gives the extraction a sense of personality and craft.
3. Progressive disclosure on the right panel: completely silent until a menu exists, then becomes active. Right call.

## Priority Issues

**[P1] Blue palette contradicts product anti-references**
- What: accent: '#3b8bbc' makes every primary button, active state, and focus ring medium blue. PRODUCT.md explicitly says "not blue-primary button hierarchies."
- Why it matters: Bar owners expect a specialist instrument. Medium blue on dark navy signals "web app built in 4 hours."
- Fix: Restore warmth. Brass/amber (oklch(72% 0.14 75)) or warm stone. The CSS variable rename from --brass to --accent has stripped semantic warmth from the token system.

**[P1] No post-action status confirmation**
- What: After saveTemplate(), addToHouseBrain(), saveMenu() complete, setStatus() is called but status only renders in the canvas empty state. Once a menu exists, users receive zero visible confirmation.
- Why it matters: Users saving templates mid-session have no idea their save took effect. Destroys trust in a library-building tool.
- Fix: Add a small persistent status line below the panel header, or a brief success banner using the existing error-banner pattern.

**[P2] Canvas background insufficient contrast with white-paper menus**
- What: canvas-bg: '#f7f9fc'. menu-bg defaults to '#ffffff'. White-paper menus nearly disappear into the canvas.
- Why it matters: The menu preview IS the product. If it doesn't clearly read as a distinct physical object, the studio metaphor breaks.
- Fix: Shift canvas to a mid-tone dark (oklch(20% 0.01 240)) or visible neutral. Dark canvas makes menus pop regardless of paper color.

**[P2] Left panel cognitive overload post-extraction**
- What: ~11 distinct elements in one block after extraction (image, button, dots, rules card, name input, 2 buttons, 2 captions, confirm UI) before user can scroll to Compose.
- Why it matters: First-time bar owners stall here. High cognitive load at the moment they should feel momentum.
- Fix: Collapse rules display to summary row with expander. Move save/merge actions to secondary block below compose.

**[P2] Block titles have visible leading spaces**
- What: " Reference Menu" and " Compose" have leading space characters. The .step-num CSS class exists but is never used.
- Why it matters: Looks like a layout bug in two prominent headings, undermining the "expertise shows in silence" principle.
- Fix: Remove spaces or add actual step numerals using the existing .step-num class.
