## Anti-Patterns Verdict

Does not read as AI-generated. No absolute bans triggered. No gradient text, no side-stripe borders, no glassmorphism, no hero metrics, no identical card grid, no modals. Right panel introduction does not break any rules — the chip palette is consistent and disciplined.

## Overall Impression

Technically substantially improved since Run 2: button contrast fixed, menu-sheet shadow visible, chip active contrast passing AA, status badge restored, dead CSS pruned, both panels now sticky. The right panel is a real workflow feature — color pickers, spacing density, title scale, content toggles, and font pickers all wired to instant re-render. But none of the Run 2 UX P1/P2s were addressed, so the heuristic score holds at 33. The remaining gap is workflow continuity: users have no safety net between generating and exporting.

## What's Working

1. **Right panel is a genuine Canva-tier control surface.** Font chips rendered in their own typeface are as good as it gets for font selection affordance. Color swatches showing live hex values, spacing density giving instant layout feel — these are correct UX choices.
2. **Sticky panels are the correct architecture.** Long menus no longer require scrolling back up to the controls. CSS grid + `position: sticky` is the right implementation.
3. **Technical audit fixes improve perceived quality.** The visible drop shadow, passing contrast ratios, and working status badge make the app feel finished rather than broken.

## Priority Issues (Carried from Run 2)

**[P1] House Brain merge has no panel-level loading indicator** (unchanged)
Merge fires a 10-30s AI call. Status badge updates but the panel block is frozen. Fix: track `merging` state, render `.extract-progress` dots below the confirm buttons during merge.

**[P2] Regenerating overwrites menu with no canvas loading state** (unchanged)
User clicks Compose Menu with an existing menu open. The old menu stays visible, nothing in the canvas changes for 15s. Only the 8px status badge signals activity. Fix: `setMenu(null)` at the top of `generate()`, restore on success, keep previous on error with explicit error path.

**[P2] Cmd+Enter keyboard shortcut is invisible** (unchanged)
The shortcut is implemented but has no hint. Fix: `<span className="kbd-hint">Ctrl+Enter to compose</span>` below the brief textarea.

## New Issues (Post Right-Panel Addition)

**[P2] Canvas can be too narrow for the A5 preview on standard screens**
The grid is `360px 1fr 280px`. At 1280px viewport that leaves 640px for the canvas. After 64px padding, effective content width is 576px. The A5 sheet is 460px wide — it fits, but barely. On a 1200px display it clips. Fix: reduce right panel to 240px, or add `min-width: 540px` on `.canvas`.

**[P3] Spacing chip feedback requires click-to-see**
Compact/Balanced/Airy chip labels are accurate but abstract. A user has to click and observe the menu shift. Fix: add `title` attributes with example values — `title="Compact: tighter sections and items"`, `title="Airy: generous breathing room between items"`. Low cost, meaningful signal.

**[P3] Right panel "Style" heading is ambiguous before generation**
The panel shows "Generate a menu to adjust its style." — correct. But the `<h1>Style</h1>` header with no further context doesn't explain that this panel affects the menu on the canvas, not the app UI. Minor. Fix: change the panel kicker from "Adjust" to "Menu Style" or subtitle the header.

## Persona Red Flags

**Jordan (First-Timer):** Generates a menu, sees it appear. Wants to change the color — finds the right panel, opens the native OS color picker, picks a color, sees the menu change instantly. This works. But then clicks Compose Menu for a variant, waits 15s while the same menu sits there, clicks again — two requests in flight. Double-compose is still a trap.

**Alex (Power User):** Right panel is a real productivity boost. Still missing: keyboard shortcut to jump to style controls, no export-to-format option (always PDF), no way to get raw JSON data.

**Sam (Accessibility User):** All style controls have labels. Font chips are labeled by font name (screen reader reads "Cormorant Garamond" — meaningful). Color inputs open native OS picker (OS-accessible). Drag repositioning has no keyboard alternative — the handle is `aria-hidden="true"` which avoids announcing a non-functional handle, but repositioning is mouse-only.

- `style={{ marginBottom: 8 }}` on the House Brain rule-line (App.jsx:294) and `style={{ color: 'var(--brass-bright)' }}` on App.jsx:305 are both inline — same pattern. Should be CSS classes.
